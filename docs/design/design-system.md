# Trip Canvas 디자인 시스템 — TDS 각색본

Toss Design System(TDS)을 이 앱에 옮긴 규약이다. **원본을 그대로 베끼지 않는다** —
토스는 금융 슈퍼앱이고 이 앱은 지도가 주인공인 개인 여행 플래너라, 색 운용과 화면 구조에서
갈라지는 지점이 있다. 아래는 **무엇을 가져왔고 무엇을 바꿨는지**만 적는다.
구현된 토큰의 실물은 `src/app/globals.css`. 결정 근거는 `decision-log.md` #48.

## 1. 가장 큰 각색 — 색의 역할을 둘로 가른다

TDS 의 핵심 규율은 **"한 화면에 강조색 하나"**(`fill-brand` = Toss Blue)다.
그런데 이 앱은 **일차 8색**(#41)과 **카테고리 3색**이 이미 정보 채널이다. 규율을 그대로 들이면
지도가 말을 잃고, 규율을 버리면 화면이 알록달록해진다. 그래서 채널을 나눈다.

| | 색 | 쓰는 곳 | 안 쓰는 곳 |
|---|---|---|---|
| **액션 색** | `--tds-bg-brand` 하나 | primary CTA · 포커스 링 · 활성 탭 · 링크 | 정보 표시 |
| **데이터 색** | `--day-*` 8색 · `--pin-*` 3색 | 지도 핀 · 일차 배지 · 타임라인 마커 | **버튼 · CTA · 강조** |

TDS 자신도 이 구분을 한다 — bar-chart 의 막대는 `grey-200` 이고 강조 막대만 브랜드색이며,
semantic red/green 은 강조색과 별개다. 이 앱의 `globals.css` 에도 원래
"정보 전달용이라 화면당 강조 1곳 원칙과 충돌하지 않는다"는 같은 논리가 적혀 있었다.

**규칙**: 버튼에 일차 색을 칠하지 마라. 일차를 나타낼 땐 색 점·배지로 옆에 두고,
버튼 자체는 브랜드색이나 `--tds-bg-secondary` 로 둔다.

## 2. 다크 모드는 이 앱이 정한다

TDS 핸드오프 번들은 **라이트 값만** 공개돼 있다(원본 Known Gaps). 이 앱은 이미 다크를 지원하므로
다크 alias 를 우리가 정의했다 — 회색 사다리를 뒤집고, 브랜드 블루는 어두운 바닥에서 읽히도록
`oklch(0.720 0.150 252)` 로 한 단계 밝힌다(hue 는 고정). pressed overlay 도 검정 26% 로는
어두운 바닥에서 보이지 않아 **흰빛 14%** 로 뒤집었다.

**일차 8색은 다크 변형을 두지 않는다**(#41 유지) — 이 색이 놓이는 바닥은 테마를 따르지 않는
지도 타일이라, 테마마다 값이 갈리면 같은 일차가 두 색으로 기억된다.

## 3. 서체

TPS(Toss Product Sans)는 외부 배포가 막혀 있다. 토스가 공식 권장하는 **Pretendard** 로 대체한다 —
메트릭·한글 자형·tabular figure 가 거의 1:1 이다. npm 대신 CDN 으로 받는 이유는 이 저장소의
lockfile 을 리눅스에서 만들어야 CI 가 통과하기 때문이다(`WORKLOG.md` 함정).

본문 기본은 TDS `body-2` = **15px / line-height 1.5 / letter-spacing -0.005em**.
금액·시간·거리처럼 자리가 흔들리면 안 되는 숫자에는 `.tabular` 를 붙인다 — 경비 합계가
바뀔 때 자릿수가 춤추지 않는다. 이 앱에서 tabular 가 필요한 곳: 경비 요약, 이동시간·거리,
일차 날짜.

## 4. 그대로 가져온 것

- **라운드 9단 사다리** `4 · 8 · 12 · 14 · 16 · 20 · 24 · 32 · full`.
  버튼은 크기와 짝지어 쓴다 — XL(56px)→16 · L(48)→14 · M(40)→12 · S(32)→10.
  iOS 류 squircle 은 쓰지 않는다.
- **평면 우선.** 그림자는 떠 있는 표면에만(`--shadow-1~3`, toast, sheet). inner shadow 없음.
  pressed 는 그림자가 아니라 **overlay**(`--tds-press-overlay`)다.
- **모션 3토큰** `120 / 200 / 320ms` + ease 2종. 바운스 오버슈트·패럴랙스·skeleton shimmer 없음.
  이 앱이 원래 갖고 있던 "장식 모션은 fade 120ms 하나뿐" 규칙과 결이 같다.
- **보더는 1px 헤어라인**(`--tds-line-default`). 포커스 입력만 1.5px 브랜드색.
  2px 장식 보더·컬러 left-rail 카드 금지.
- **해요체 · 위임형 · 일상어.** 이 앱의 기존 관례(`AGENTS.md`)와 이미 같다.
  버튼 라벨은 일어날 일을 직접 말한다 — "보관함에 담기", "일정에 넣기".
- **Navigating error.** 에러 화면은 멈춰 세우지 않고 다음 행동 버튼을 준다.
  이 앱의 L-06(막다른 화면 금지)과 같은 규칙이다.
- **금액 표기** `1,000원` — 세 자리 구분 + `원` 붙여쓰기.

## 5. 안 가져온 것

- **토스의 금융 도메인** — 송금 플로우·계좌 목록·keypad 같은 화면 시퀀스. 원본 Don'ts 가
  명시적으로 금지한다: 차용할 것은 시각 언어이지 금융 서비스 개념이 아니다.
- **`{component.bottom-cta}` 단일 규율** — 토스는 화면 최하단 고정 CTA 가 1차 액션의 자리다.
  이 앱의 모바일 하단은 **네비게이션 탭**(지도·보관함·일정, #42)이 이미 차지하고 있다.
  둘을 겹쳐 쌓지 않는다 — 화면 안 액션은 `button-primary` 로 둔다.
- **이모지 inline** — 토스는 카피에 이모지를 넣지 않고 큐레이트된 일러스트 자산만 쓴다.
  이 앱의 하단 탭이 쓰던 🗺·🔖·🗓 는 **아이콘으로 바꾼다**.
- **Tossface 일러스트 세트** — 라이선스·주제 모두 이 앱과 맞지 않는다.
  빈 상태는 아이콘 + 해요체 한 줄로 처리한다.

## 6. 컴포넌트 매핑 (이 앱 → TDS)

| 이 앱 | TDS 대응 | 규격 |
|---|---|---|
| 검색 입력(`PlaceSearchBox`) | `search-field` | 48px · radius 12 · resting `surface-2` · focus 흰 배경 + 1.5px 브랜드 |
| 하단 메뉴(`CanvasBoard`) | `tab-bar` | active = filled 아이콘 + `fg`, inactive = outline + `fg-3` |
| 장소 카드(`PreviewCard`) | `bottom-sheet` / `dialog` | radius 20 · `--shadow-3` · scrim `--tds-bg-overlay` |
| 일차 탭 | `tab` | 하단 2.5px 브랜드 언더라인 |
| 타임라인 행(`TimelinePane`) | `list-row` | 44px 슬롯 + 타이틀/서브 + 우측 금액 |
| 보관함 행(`ListPane`) | `list-row` | 위와 같음 |
| 별표(#46) | `rating` | 채운 별 `--color-star`, 빈 별 `--tds-line-strong` |
| 확정 토글(#47) | `checkbox` | 22px · radius 6 · checked 는 브랜드 배경 + 흰 체크 |
| 경비 요약 | `table-row` | 라벨/값 2열 · 헤어라인 구분 · 값은 `.tabular` |
| 금액 입력 | `text-field` | 48px · radius 12 · 숫자는 `.tabular` |

## 7. 지도 위에서의 예외

TDS 는 지도를 다루지 않는다. 이 앱에만 있는 규칙:

- 지도 위에 뜨는 표면(장소 카드·핀 팝업)은 **`--shadow-3`** 를 쓴다. 지도 타일은 배경 대비를
  보장하지 않으므로 헤어라인만으로는 표면이 안 떠 보인다.
- 지도 컨테이너는 **`relative` 부모 + `absolute inset-0`** 으로 채운다. `h-full` 은 flex 아이템
  안에서 퍼센트 기준을 못 잡아 지도가 백지로 뜬다(두 번 겪음 — `src/components/CLAUDE.md`).
- 핀 안의 흰 글자가 읽혀야 하므로 일차 팔레트는 CHECK 로 가둔 8색만 쓴다(#41).
