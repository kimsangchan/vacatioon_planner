# Seed — 여행 플래너 (가칭 "Trip Canvas")

- 조사·작성일: 2026-08-06
- 원문: "여행 플래너 앱을 만들고 싶어. 이동, 숙박, 식당, 스팟 등에 대한 정보를 정말 쉽게 유저 친화적 UI/UX로 기록해둘 수 있었으면 좋겠어. 예를 들면 네이버지도에서 맘에 든 집을 저장하면 해당 식당을 지도에 표시해주고 마우스 호버하면 사진을 유저 친화적 UI를 최대한 활용해서 볼 수 있게 해주는 거지. 숙박도 마찬가지고 스팟도 같지. 이동 같은 경우에는 예매 일정 정보, 출발 시간, 도착 시간 같은 걸 한눈에 쉽게 볼 수 있는 구조여야겠지? 이외에도 여행 플래너에 필요한 블라인드 스팟을 채워주고 질문을 하고 기획을 세워보자. 가장 중요한 건 정말 직관적으로 보여줬으면 좋겠어 — 클릭이 많다던가 뎁스가 깊어지지 않아야 한다는 거야. 아이폰을 쓰면 앱을 배포하기 힘드니까 우선 웹페이지 형태로 시작을 해야 하나? 이것도 추천을 먼저 해줄래."

- 서비스 유형: **웹 앱 (지도 중심 개인 여행 플래너)** — 모바일 사용 전제(아이폰) → 반응형 웹/PWA 후보
- 주 도메인: 여행 계획 (trip planning — 장소 저장·일정 구성·이동 정보 통합)
- 인접 도메인: 지도/POI 검색 (map & places), 일정 관리 (itinerary/scheduling)

- 감지된 제약:
  1. 사용자 기기 = 아이폰 → App Store 배포 부담을 인지, 웹 우선을 스스로 검토 중 (추천 요청됨)
  2. 핵심 품질 요구 = "직관적" → 클릭 수·뎁스 최소화 (quality-decomposition 변환 대상)
  3. 참조 제품 = 네이버지도 (저장 → 지도 핀 표시 → 호버 시 사진 미리보기)
  4. 정보 카테고리 4종 확정: 이동(교통·예매·출발/도착 시각), 숙박, 식당, 스팟
  5. 개발 주체 = 1인 (추정 — 개인 프로젝트 디렉토리 `D:\_personal\vacation`)

- 로드할 블라인드스팟 프로파일: **P2(웹 SaaS) + P4(모바일 앱) 합집합** + 여행 플래너 임시 프로파일(공통 10축 스캔에서 작성 — 프로파일에 없는 도메인 절차 적용)

- 미해석 항목 (A1~A2에서 채움):
  - "네이버지도에서 저장하면" — 네이버지도 저장 목록의 외부 연동 가능 여부는 조사 필요 (A1)
  - 여행 지역 범위(국내/해외) — 지도 SDK 선택을 좌우 (A2 질문 후보)
  - 사용 주체(개인용/공개 서비스) — 인증·백엔드 복잡도를 좌우 (A2 질문 후보)
