# PRD — Trip Canvas (여행 플래너)

작성 2026-08-06 · 근거: 00-seed, 01-recon, 02-blindspot-register, decision-log #1~#10

## 배경

여행 계획은 수집(장소 저장) → 배치(날짜·동선) → 확정(교통·숙박 예매 기록) → 여행 중 참조의 4단계로 이뤄진다(01-recon). 기존 도구는 예약 커머스 중심(트리플)이거나 영어권 POI 중심(Wanderlog)이라, "네이버지도에서 찾은 장소를 마찰 없이 지도 위에 쌓고 한눈에 보는 개인 기록 도구"가 비어 있다. 네이버지도 저장 목록의 공식 연동 API는 없으므로(01-recon 핵심 발견 1) 앱 내 검색(네이버 지역 검색 API)으로 같은 가치를 제공한다. 플랫폼은 반응형 웹+PWA(결정 #1), 지도는 국내 네이버 → 해외 구글 병행(결정 #2, MVP는 국내).

## 용어 (축 8 해소)

| 용어 | 정의 |
|---|---|
| 여행(Trip) | 이름·기간을 갖는 최상위 단위 |
| 일차(Day) | Trip 기간 내 하루. Trip 생성 시 자동 생성 |
| 장소(Place) | 저장된 지점. 카테고리 = `restaurant`(식당)·`lodging`(숙박)·`spot`(스팟) 3종 고정 |
| 보관함(Unassigned) | 저장했지만 아직 일차에 배치하지 않은 Place 상태 |
| 일정 항목(Stop) | Place를 특정 Day에 순서를 갖고 배치한 것 (시각은 선택 입력) |
| 이동(Leg) | Day에 속한 교통 기록 — 유형·출발/도착 시각·출발/도착 지점·예약번호·가격·메모 |
| 캔버스(Canvas) | 한 Trip의 지도+리스트 통합 메인 화면 |

## 제품 목표 (≤3, 직교)

1. **마찰 없는 수집** — 장소를 떠올린 순간부터 저장 완료까지 3클릭·10초 이내 (UX-01)
2. **한눈 파악** — 지도·일정·이동 정보가 뎁스 2 이내에서 스크롤 최소로 파악됨 (UX-02·UX-06)
3. **여행 중 즉답** — 이동 중 아이폰에서 "지금/다음 일정"을 조작 없이 확인 (UX-05)

## 엣지케이스 (Given/When/Then)

**수집 (US-1)**
- Given 검색어 결과 0건, When 검색하면, Then "결과 없어요 + 철자·다른 이름 제안 + 좌표 직접 찍기(지도 롱프레스) 대안"을 표시한다 (막다른 에러 금지 — L-06)
- Given 네이버 API 오류·쿼터 초과, When 검색하면, Then 캐시된 최근 검색을 표시하고 "잠시 후 다시" 안내, 서버는 쿼터 경보를 기록한다 (07 연계)
- Given 같은 좌표·이름의 Place가 이미 있음, When 저장하면, Then 중복 안내 후 기존 항목으로 이동을 제안한다 (덮어쓰기 금지)
- Given KATECH→WGS84 변환 실패(비정상 좌표), When 저장하면, Then 지도 미리보기로 위치 확인을 요구하고 확인 전 저장하지 않는다

**조회 (US-2)**
- Given 사진 없는 Place, When 호버/탭하면, Then 카테고리 아이콘 플레이스홀더 + "사진 추가" 단축 버튼을 표시한다 (기능은 성립)
- Given 좁은 영역에 핀 5개 이상 겹침, When 지도 표시하면, Then 클러스터로 묶고 클릭 시 확대한다
- Given 모바일(호버 불가), When 핀 탭하면, Then 바텀시트 미리보기를 표시하고 두 번째 탭에서 상세로 간다 (뎁스 2 유지)

**배치 (US-3)**
- Given Day에 배치된 Stop 존재, When Trip 기간을 줄여 해당 Day가 삭제되면, Then Stop을 삭제하지 않고 보관함으로 되돌리며 개수를 안내한다 (데이터 손실 금지)
- Given 도착 시각 < 출발 시각인 Leg 입력, When 저장하면, Then 익일 도착(+1d) 여부를 물어 확정한다 (야간 이동 실사용 케이스)
- Given 시각 미입력 Stop과 시각 입력 Leg 혼재, When 타임라인 표시하면, Then Day 내 통합 position 순서(Stop·Leg가 하나의 순서 공간 공유 — 결정 #15)가 유일한 정렬 기준이고 시각은 표시 정보다. 입력된 시각이 position 순서와 역전되면 해당 항목에 경고 배지를 표시한다

**공유 (US-4)**
- Given 공유 링크가 외부에 유출됨, When 소유자가 공유를 끄면, Then 기존 토큰은 즉시 403이 된다

## UI 방향 (ux-principles-kr 적용, frontend-design-taste 연계)

- **레이아웃**: 데스크톱 = 좌측 리스트 패널(보관함+일차 탭) / 우측 지도 고정의 단일 캔버스. 모바일 = 지도 상단 + 하단 시트 리스트(끌어올리기). 별도 페이지 이동 최소화 — 뎁스 2 상한 (SC-003)
- **다크패턴 방지**: 진입 시 모달 금지(T-04), 삭제·되돌리기 항상 가능(T-06), CTA는 행동 서술형 라벨 — "저장" 대신 "보관함에 담기" (T-08)
- **문구**: 해요체·능동형·긍정형 (T-09~T-11). 에러에는 항상 다음 행동 제시 (L-06)
- **밀도·모션 dial** (frontend-design-taste, BUILD 단계 적용): 밀도 = 중간(정보 도구지만 여행의 경쾌함 유지), 모션 = 절제(호버 카드 fade 120ms·시트 슬라이드만, 장식 모션 금지). 강조색 = 카테고리 3색(식당/숙박/스팟) + 중립 배경 — 화면당 강조 1곳 원칙(L-09)과 충돌하지 않게 핀 색은 정보 전달로 간주(T-14)
- **입력 관대함**: 장소 추가는 검색·지도 롱프레스 모두 허용 (L-05)

## 범위 밖 (non-goals — 합리적 목표였지만 명시적으로 제외)

1. 예약·결제·커머스 (트리플의 영역 — 우리는 기록 도구)
2. 실시간 공동 편집 (결정 #10 — 읽기전용 공유로 충분)
3. 경비 정산의 계산·분배 기능 (검증된 대안 존재). 단 **금액 기록 자체는 범위 내** — Leg 가격 필드와 Day 합계 표시로 저장해두어 나중에 정산이 가능하게 한다 (사용자 피드백, 결정 #17)
4. 네이버지도 저장목록 자동 연동 (기술적 불가 — 01-recon), 공유링크 파싱 (2단계 후보)
5. 예매처(코레일 등) 연동·메일 파싱 (공개 API 부재 — 결정 #7)
6. AI 추천·자동 일정 생성 (수집·기록 가치와 직교 — 범위 방어)
