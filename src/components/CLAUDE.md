## 핵심 관례

- **지도 SDK를 컴포넌트에서 직접 import 하지 마라.** `src/lib/map`의 `MapProvider`만 소비 (#2)
- 지도 인증은 mount **이후 비동기로** 실패할 수 있다 — SDK가 네임스페이스를 비운다.
  `navermap_authFailure` 훅 구독 + SDK 호출 방어 + 안내 배너를 유지하라(회귀 테스트 3건 존재)
- **Day 내 순서는 통합 `position`.** 시각으로 정렬하지 마라 (#15).
  Day 지출 합계 = Stop + Leg (#24)
- 사용자 대면 문구는 해요체·능동형·긍정형. CTA는 다음 행동을 서술("보관함에 담기").
  **에러 화면엔 항상 다음 행동 버튼**
- 저장 결정은 3지점 유지 — 카테고리 버튼("식당으로 담기")이 곧 저장 (T6-2)
- iOS 설치형 PWA는 Safari와 세션이 격리된다 — 인증 기본은 **OTP 코드 입력**, 매직링크는 보조 (#13)
- 핀 겹침(클러스터링)은 미해결 — 별도 라이브러리 필요로 보류(T6-3)

## 함정 (실측으로 얻은 것 — 유닛 테스트가 놓친 것들)

- **jsdom 에는 레이아웃이 없다.** "DOM 에 있다"만 단언하면 화면 밖으로 잘린 결함이 그대로 통과한다.
  카드가 안 보인다는 신고를 테스트가 3번 연속 놓쳤다 — 위치·부모·시트 높이로 단언하라
- **지도 SDK 의 `fromCoordToOffset` 은 월드 픽셀이다**(화면 좌표 아님). 뷰포트 북서 모서리
  (NE.lat + SW.lng)를 투영해 빼야 컨테이너 기준이 된다. 유닛 테스트로는 못 잡는다 — 끌어 봐야 나온다 (#40)
- **`h-full` 은 flex 아이템 안에서 퍼센트 기준이 확정되지 않는다** — 지도 컨테이너가 0px 이 되어
  지도가 **백지**로 뜬다. 부모를 `relative` 로 두고 `absolute inset-0` 로 채워라 (두 번 겪었다, #42)
- **끌기를 받을 땐 `setPointerCapture`.** 없으면 요소 밖으로 나가는 순간 `pointermove` 가 끊긴다.
  유닛 테스트는 좌표를 직접 쏘므로 통과하고 실제 손가락에서만 안 먹는다 (#44)
- **같은 컴포넌트를 반응형으로 두 벌 두지 마라** — `id` 하드코딩이 있으면 문서에 같은 id 가 둘 생겨
  라벨이 엉뚱한 입력에 붙는다 (`PlaceSearchBox` 의 `id="place-search"`, #42)
